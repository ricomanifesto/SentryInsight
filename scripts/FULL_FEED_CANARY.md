# Full-feed canary preparation

The closed offline rehearsal uses the actual frozen feed parser, source review,
Kimi prompt, model completion parser, finding/version validation, static renderer
and Pages packager. It has no live mode and never reads a provider credential.

Run with the existing frozen dependencies and verified tokenizer cache:

```sh
.venv/bin/python -I -B scripts/rehearse_full_feed_canary.py \
  --offline-only --feed-file /absolute/path/to/hash-verified-feed.xml
```

The accepted packet is the 30-entry November 5 preparation snapshot. No article
URL is fetched. All 30 entries are source-bound; 25 eligible entries enter model
context and five held entries remain disclosed as partial coverage. The output
contains only bounded hashes, counts, fixed diagnostics and synthetic operation
state. The handcrafted response is a host-only positive control, never model
input or evidence of live model quality. The grounded example uses an unknown
exploitation status where the existing recognizer does not confirm the wording.
No parser or validator is relaxed to obtain that result.

The local financial owner uses the actual admission/daily/spending components
and a disposable local-file Git CAS branch. Its fictional opening assertion does
not initialize a real pilot or create spending authority. One acknowledged
`beginSend` supplies the SAME original request token, with physical limit one,
before the single mock outer POST. The reply is replayed through an owned mock
client without issuing a second token or another external request. The complete
wire bytes must match both preparation and replay. There is no retry or repair.

The whole 7,251,456 microUSD ordinary episode hold remains reserved even though
the physical limit is one. It uses the model-context assumption (1,048,576 input
units at 2 microUSD plus 32,000 combined completion units at 10 microUSD, times
three ordinary slots), not the cl100k estimator as a billing guarantee. The
known synthetic usage is recorded with billing coverage unknown; there is no
refund or claim of actual account cost. Null serving tier remains unavailable
metadata, never fabricated as an attestation of default service.

This rehearsal is date-bound to November 5, 2026 and refuses another UTC date
before issuing a grant. The prompt date is reproducible. A validated scratch
report receives the actual host generation timestamp, not the capture's fixed
future time. Successful output is promoted only inside disposable scratch and
packaged there. Failed, empty, incomplete-accounting or ungrounded replies
preserve the copied last-good artifacts. There is no public Git write, publisher
or production modification. Scratch output is discarded at CLI exit.

The capture helper seals inherited credentials, model overrides, gateway and
exporter configuration before application imports. It denies real socket and
HTTP transport and checks exact model/client/mock ownership. This operation
owns its process environment exclusively; it is not a concurrently callable web
service. Use the trusted isolated interpreter invocation above. It cannot undo
untrusted interpreter startup hooks that ran before the process entered it.

A real canary still requires a separately reviewed closed sender and persistent
admission store, missing activation/opening and billing decisions, approved
public operational-metadata audience, exact source/privacy transmission scope,
conditional promotion or draft-disposal fate, and publication/execution approval.
The disposable fixture must never be substituted for that persistent authority.
Ordinary selected clients remain OFFLINE-only; this rehearsal is not recurring
production activation or proof that the stale serving report has recovered.

The separately proposed [closed persistent execution route](SENTRY_CANARY_EXECUTION.md)
now defines that future adapter. Its committed activation/opening/billing/data
and audience gates remain missing; the offline rehearsal is still the default
and supplies no real execution authority.
