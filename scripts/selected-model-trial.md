# Fixed fictional model trial

This temporary test branch contains a manual, nonpublishing executor for two fixed fictional requests. It does not enable the selected production model routes. Do not merge this branch's workflow or deployment guard into main.

The registered `verify-nemotron.yml` workflow is reused only on `test/selected-model-fixtures-20261104`. Its required `expected_commit` input must equal the reviewed executor SHA. Only the repository owner's first manual run is eligible. Public run history rejects another dispatch at that SHA, and a private, exclusive, fsynced claim marks each request as sending before HTTP. A stopped or uncertain run needs inspection; rerunning is not a repair mechanism.

The executor checks out these source commits separately:

| Project | Source commit | Model | Standard endpoint | Conservative input / combined output |
|---|---|---|---|---|
| SentryInsight | `4833a2907cff7690a333d9c80825c8339a270e2d` | `moonshotai/kimi-k3.1-pro` | `moonshotai/mxfp4` | 20,000 / 32,000 |
| GRCInsight | `800d2f572dc1b4d2a26f4c74fe9b08f33e455c6a` | `google/gemini-4-argon` | `google-ai-studio` | 22,000 / 8,000 |

Sentry's case includes the eligible fictional Example Gateway advisory and the normal public Markdown prompt. The ambiguous held source and handwritten calibration answer are excluded. GRC's case includes two fictional notices on `.test` URLs, fixed analysis/feed fields and the public strict plan schema. Its handwritten calibration plan is excluded. No source URL is fetched and no article-analysis operation runs.

Both exact payloads are generated by the accepted OFFLINE clients with a synthetic key and MockTransport, then checked against fixed fixture, canonical JSON and wire-byte hashes in `scripts/verify_selected_models_once.py`. Their real answers are replayed locally through those clients and the production grounding, source coverage and rendering checks. Empty GRC plans fail the positive supplier-control oracle. Reports and answers exist only in removed scratch or bounded memory; neither source checkout nor public reports are written.

The separate sender posts the prepared bytes once per model to OpenRouter. It has no redirects, transport retries, provider fallback, tools, search, extra URL retrieval, account calls or balance lookup. Provider and standard-tier filters, low excluded reasoning, collection denial, ZDR filtering and text rates of at most $2/M input plus $10/M combined output are fixed. The maximum estimate is $0.360 + $0.124 = $0.484 against a shared $2 reservation. Input units are conservative byte/reserve estimates, not provider tokenizer measurements. Requested privacy/routing filters do not prove account eligibility or serving-provider attestation.

Only the sender step receives the existing Sentry Actions `OPENROUTER_API_KEY`. Preparation and replay children receive no real inference, GitHub or AWS credentials. No key is copied to GRC. Missing returned usage, cost, tier or provider remains unknown. Missing/null actual tier or missing/inconsistent prompt, completion, total and cost accounting stops before another allocation. Serving-provider metadata is not mandatory in the documented response schema; its absence alone does not imply attestation or stop the sequence. HTTP, transport, identity, wrong tier, accounting and unavailable or malformed replay failures stop the sequence. A known complete answer that fails only host validation may be recorded before proceeding to the independent second case; it never triggers regeneration.

Explicit sanitized metadata files are retained for seven days. They contain fixed outcomes, identities, numeric usage/cost when supplied, hashes, counts and claim states. Raw prompts, answers, reasoning, error bodies and headers are excluded. Workflow permissions are `contents: read`; there is no publisher or Git writer. Both remote main commits and public report blob hashes are fenced before and after the trial.

The temporary branches include `vercel.json` with `git.deploymentEnabled: false`. Existing Actions deployment listeners target main. Actual Git integration and project root configuration must also be verified before branch publication; this repository file alone is not proof of hosting effects. GRC's existing authentication failure is a separate issue, and this one report-plan trial does not validate the full production workflow or repair credentials.

Frozen dependencies use separate Python 3.11.11 environments and the existing hash-verified tokenizer cache. Local focused tests require the accepted Sentry/GRC source directories, a Sentry interpreter, the GRC locked interpreter and tokenizer cache, supplied through the `SELECTED_TRIAL_*` and `TIKTOKEN_CACHE_DIR` environment variables documented by the test fixture. Local tests use network fakes only.
