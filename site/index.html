Exploitation ReportNovember 13, 2026

Executive Summary

Check Point Software has released emergency hotfixes for a local privilege escalation flaw tracked as CVE-2026-123039 in the Gaia OS DynamicCLI interface, which attackers have used to gain root privileges and establish persistence on vulnerable security gateways and management servers. The exploitation chain began with PHP2Shell vulnerabilities against Mobile Access portals, followed by privilege escalation through the DynamicCLI interface, deployment of the TSGA backdoor and TSProxy component, and lateral movement to VMware ESXi hosts where destructive wiper malware was deployed. Check Point observed active exploitation against a couple of dozen customers, though the scoped assessment for this CVE remains unknown per the supplied evidence contract.

Separately, the N-able N-central zero-day dubbed 4EverAble2Shell was actively exploited within hours of public proof-of-concept release, chaining Apache Axis vulnerability CVE-2026-90436 with an N-central privilege escalation weakness to deploy XMRig cryptocurrency miners across at least 21 production servers, including 19 running the latest Hotfix 2 update. Researchers confirmed successful compromise of N-central infrastructure used by managed service providers, with attacks traced to attacker-controlled IP address 157.20.241[.]16.

Additional findings with uncertain or not_observed exploitation status include ScreenConnect flaw CVE-2026-84869 (not_observed despite SCKit toolkit activity), multiple Red Hat Quay critical flaws (CVE-2026-123710 and CVE-2026-110697), Apache HTTP Server mod_http2 remote code execution (CVE-2026-119618), and numerous other vendor advisories where exploitation status is assessed as unknown based on the supplied evidence. No confirmed active exploitation is asserted for any CVE beyond what the scoped contract explicitly assigns.

Vendor guidance: nvd.nist.gov, support.checkpoint.com

Earlier reporting
  • CVE-2026-123039. First report of this CVE in the retained archive.
  • Description: Local privilege escalation vulnerability in the DynamicCLI IPC (Inter-Process Communication) interface used to send privileged command requests to the root-level Gaia OS DynamicCLI (dynamic_server) daemon. The daemon runs as root and listens on a world-writable local socket (/tmp/dynamic_socket) without authenticating connecting processes, allowing an authenticated local user to send a command to the socket and have it executed as root.
  • Impact: Attackers can gain root privileges and establish persistence on vulnerable Check Point devices, enabling full compromise of security gateways and management servers.
  • Status: Emergency hotfixes released; temporary mitigation involves stopping the dynamic_server process and preventing it from restarting.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: None stated in supplied sources.
  • Recommended Actions: Check Point advised security teams who can't immediately deploy the CVE-2026-123039 hotfixes to stop the dynamic_server process and prevent it from restarting as a temporary mitigation measure; customers can find evidence of compromise by checking for commands commonly associated with exploitation attempts, the use of the system() sink, and commands that don't use the default Clish wrapper.

Vendor guidance: access.redhat.com, access.redhat.com (2)

Earlier reporting
  • CVE-2026-123710. First report of this CVE in the retained archive.
  • Description: Critical flaw in Red Hat Quay allowing an attacker who can access a Quay registry to read and overwrite private container images in every repository. Quay uses trusted keys to sign access tokens; the flaw lets an attacker add their own key to the trusted keys with no expiry date, enabling tokens signed with that key to be accepted for any repository. Quay enables anonymous access by default, requiring no account for exploitation when enabled.
  • Impact: Attackers can retrieve private images and any secrets or credentials stored within them, push or overwrite images (propagating to all systems that later pull those images), delete trusted keys causing authentication failures, and establish persistent access via planted keys that survive restarts.
  • Status: Fixed builds released for eight Quay 3 branches; Quay.io already fixed for the related flaw; proxy/load balancer mitigation available for /keys endpoint.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: None stated in supplied sources.
  • Recommended Actions: At the proxy or load balancer, block the /keys endpoint for everything except trusted internal components; search audit logs for service_key_rotate and service_key_delete events where expiration_date is null; remove unrecognized approved service keys; install the fixed release.

Vendor guidance: access.redhat.com

Earlier reporting
  • CVE-2026-110697. First report of this CVE in the retained archive.
  • Description: Second critical flaw disclosed alongside CVE-2026-123710, allowing a Quay user who can create a namespace to steal other tenants' robot account tokens. The flaw is in robot account listing code that builds an SQL LIKE pattern from namespace name without escaping wildcard characters, enabling namespace name collision and unauthorized access to decrypted robot account tokens.
  • Impact: Attackers can read, push, or overwrite other tenants' images; deleting the attacker's namespace deletes corresponding robot accounts, cutting off systems that rely on them; stolen credentials can inject malicious images into CI/CD pipelines where Quay is the integrated registry for OpenShift.
  • Status: Updating is the only complete fix; Quay.io already fixed; limiting namespace creation with underscores and rotating robot tokens are interim measures.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: None stated in supplied sources.
  • Recommended Actions: Limit who can create organizations or namespaces containing an underscore; rotate robot tokens for any namespace that matches an underscore namespace; watch for pulls or pushes that do not fit normal robot use; install the fixed release.

Attack Vectors and Techniques

  • Local Privilege Escalation via World-Writable Socket: Authenticated local users send commands to the unauthenticated DynamicCLI socket (/tmp/dynamic_socket) on Check Point Gaia OS, achieving root-level command execution without authentication of connecting processes.
  • PHP2Shell Initial Access: Attackers exploit PHP2Shell vulnerabilities against Check Point Mobile Access portals to obtain initial access, then escalate privileges through the DynamicCLI interface to root.
  • Apache Axis SOAP Fault Exploitation: Crafted SOAP requests trigger unsafe class instantiation during fault processing in the bundled Apache Axis component, causing attacker-selected JLine classes to process malicious input and execute commands as the nable service account.
  • Privilege Escalation via Symbolic Link Abuse: N-central privilege escalation stage abuses the privileged setLDFileOwner helper and symbolic links to make root-owned scripts writable, then invokes serverControl functionality to execute commands as root.
  • Container Image Token Manipulation: Attackers add their own signing key to Red Hat Quay's trusted key store, enabling forgery of access tokens for any repository and read/write access to private container images.
  • SQL LIKE Wildcard Namespace Collision: Unescaped namespace names in SQL LIKE queries allow underscore pattern matching to return other tenants' robot accounts with decrypted tokens.
  • HTTP/2 Heap Corruption Race Condition: Concurrent execution using shared resources with improper synchronization in mod_http2 assign_headers() causes heap memory corruption leading to remote code execution.
  • ScreenConnect Session Hijacking and RelayTrap: Malicious ScreenConnect Guest processes replace legitimate ones to intercept technician connections, send malicious files in reverse direction, and steal authenticated management session cookies from browser data.
