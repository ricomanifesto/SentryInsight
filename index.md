Recent exploitation activity centers on open-source and infrastructure components. CISA added four flaws to its Known Exploited Vulnerabilities catalog, including OpenSSH authentication bypass CVE-2026-123158 (SSHole), GPUStack CVE-2026-102895, SignalWire FreeSwitch CVE-2026-116779, and IBM Aspera Faspez CVE-2026-123218; exploitation evidence varies from confirmed attempts to unspecified in-the-wild reports. Google patched Chrome XML use-after-free CVE-2026-125350, its eighth actively exploited zero-day of the year, alongside previously patched Chrome flaws.

Supply chain and trust-abuse incidents also featured prominently. Attackers compromised Ethersphere's release automation to distribute malicious bee-js 13.3.0 and Swarm Desktop 0.56.2 capable of stealing cryptocurrency wallet keys and installing backdoors. Separately, N-able took N-central cloud environments offline after a researcher disclosed more than 30 alleged zero-days with proof-of-concept exploits, though the vendor reported no observed active exploitation.

Threat actor activity included Iranian state-backed Shahid Kaveh linked to sabotage of refrigeration controllers at roughly 700 French retail sites, and the South Asian espionage group Bitter deploying the PapRAT remote access trojan across multiple infection chains. Defenders should prioritize patching where fixes exist and review trust relationships in CI/CD, cloud IAM, and software update channels.

## Active Exploitation Details

### CVE-2026-123158 OpenSSH SSHole authentication bypass
- **Description**: The SSHole vulnerability in OpenSSH affects certain musl-based Linux systems, including Alpine, where an oversized password causes musl's password-hashing function to return an asterisk on error that OpenSSH mistakenly treats as a match for accounts whose stored password hash is an asterisk, enabling authentication bypass.
- **Impact**: Attackers can log in to password-disabled accounts, execute commands, steal credentials, read password hashes and root SSH keys, modify authorized_keys for persistence, and potentially achieve root access where the compromised account has passwordless administrative privileges.
- **Status**: OpenSSH maintainers fixed the vulnerability in version 10.6p2 released November 5; exploit code became available roughly four hours later. Exploitation attempts were reported beginning November 5, with successful exploitation recorded subsequently. System administrators should update OpenSSH or disable SSH password authentication on affected systems.
- **Severity**: high
- **Exploitation Status**: potential
- **Action**: patch
- **CVE IDs**: CVE-2026-123158
- **Reporting**: [Bleeping Computer — Hackers exploit SSHole OpenSSH flaw to breach Linux systems](https://www.bleepingcomputer.com/news/security/hackers-exploit-sshole-openssh-flaw-to-breach-linux-systems/), [The Hacker News — CISA Warns of Active Exploitation of OpenSSH, GPUStack, FreeSWITCH, and IBM Flaws](https://thehackernews.com/2026/11/cisa-warns-of-active-exploitation-of.html), [The Hacker News — ⚡ Weekly Recap: SSHole Exploited, APT Root RCE, Robot Takeovers, 15K Hacked Sites, and More](https://thehackernews.com/2026/11/weekly-recap-sshole-exploited-apt-root.html)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: Accounts with valid password hashes are not affected; exploitation requires specific authentication settings, including PAM disabled on musl-based Linux.
- **Recommended Actions**: System administrators should update OpenSSH as soon as possible, or disable SSH password authentication on systems affected by SSHole.; It is also recommended to check for unexpected successful password logins to accounts whose /etc/shadow password field is *, unauthorized SSH keys, and TAC Agent files or startup services.
- **Vendor Links**: https://www.openssh.org/releasenotes.html; https://previdian.com/CVE-2026-123158; https://www.cisa.gov/known-exploited-vulnerabilities-catalog; http://sshole.events.greynoise.io/

### CVE-2026-125350 Google Chrome XML use-after-free zero-day
- **Description**: A high-severity use-after-free bug in the XML component of Google Chrome, where the XML parser processes data, deletes an object from memory, but fails to clear the pointer referencing that object.

- **Status**: Google released emergency updates for Chrome Stable Desktop versions 157.0.8103.50/.51 on Windows and macOS and 157.0.8103.50 on Linux; Google acknowledged it is aware an exploit exists in the wild but shared no additional details on abuse or attribution.

### Ethersphere bee-js and Swarm Desktop malicious supply chain releases
- **Description**: Attackers used Ethersphere's release automation account bee-worker to publish malicious versions bee-js 13.3.0 and Swarm Desktop 0.56.2; both download and run code to steal Swarm Desktop wallet keys and stored passwords and install a backdoor on Windows, macOS, and Linux.
- **Impact**: Theft of node wallet keys, xDAI and xBZZ tokens, chequebook funds, and stake; persistent backdoor access (evjawbreaker on Linux/macOS, ScreenConnect on Windows) on compromised machines.
- **Status**: Malicious releases were withdrawn; clean Swarm Desktop 0.56.3 and bee-js 13.2.0 were restored. Removal of the app or package does not remove an already-installed backdoor.
- **Severity**: unknown
- **Exploitation Status**: unknown
- **Action**: mitigate
- **Reporting**: [The Hacker News — Hackers Compromise Ethersphere's bee-js and Swarm Desktop to Deliver Wallet-Stealing Malware](https://thehackernews.com/2026/11/hackers-compromise-etherspheres-bee-js.html)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: Intel Macs were never offered Swarm Desktop 0.56.2 through automatic updates; Linux installs do not update automatically.
- **Recommended Actions**: Pin @ethersphere/bee-js@13.2.0 and clear cached copies of 13.3.0, including npm mirrors.; Install Swarm Desktop 0.56.3; on Linux, replace the package by hand.; If 0.56.2 ever ran, treat the node key and password as stolen and move funds, chequebook, and stake to a new key from a clean computer.; Where possible, rebuild the machine from a trusted image instead of cleaning it in place.
- **Vendor Links**: https://github.com/ethersphere/swarm-desktop/releases/tag/v0.56.3; https://socket.dev/blog/bee-js-compromise; https://safedep.io/blog/ethersphere-bee-js-npm-compromise; https://github.com/advisories/GHSA-hh7j-5m3j-23pf

## Affected Systems and Products

- **OpenSSH on musl-based Linux (including Alpine)**: Systems running OpenSSH with PAM disabled and accounts whose password hash is set to an asterisk.
- **Google Chrome**: Windows, Apple macOS, and Linux desktop installations before the patched 157.0.8103.50/.51 or 157.0.8103.50 releases.
- **GPUStack**: Deployments before the July 2026 fix.
- **IBM Aspera Faspex**: Instances before the November 2026 fix.
- **SignalWire FreeSwitch**: Deployments before the October 2026 fix.
- **Flowise**: Instances exposed online, especially those without authentication enabled.
- **Swarm Desktop and bee-js**: Windows x64 and Apple Silicon Macs that received Swarm Desktop 0.56.2 auto-update; projects installing @ethersphere/bee-js@13.3.0 from npm during the malicious window.
- **N-central**: Hosted and on-premise N-able N-central environments across Americas, APAC, and Europe.
- **Refrigeration controllers**: Danfoss AK-SM and AK-SC series, Copeland xweb, and Dixell xweb at retail sites.

## Attack Vectors and Techniques

- **SSHole authentication bypass**: Oversized password input causes musl password-hashing to return an error asterisk that OpenSSH treats as a match for disabled-password accounts.
- **Supply chain compromise**: Stolen CI credentials used via project release automation to publish signed malicious npm and desktop releases; postinstall script and app startup loader fetch second-stage payloads from attacker-controlled domains.
- **Default administrator credentials and path confusion**: ForgeRock/OpenIDM Apache Felix console left at default admin:admin; encoded slashes caused edge and server to interpret paths differently, bypassing WAF restrictions.
- **Cloud trust relationship abuse**: Stolen Qubole AWS credentials used to assume customer IAM roles via AssumeRole with valid External ID from non-AWS source IPs; secrets read from Lambda environment variables, Secrets Manager, SSM Parameter Store, and S3 buckets.
- **Industrial controller sabotage**: Remote access to Danfoss and Dixell refrigeration controller web interfaces to alter defrost settings and disable temperature safety alerts.
- **PapRAT infection chains**: Malicious LNK files abusing ftp.exe, VHDX disk images with Excel lures, and URL shortcuts fetching payloads via WebDAV; MSI installers deploy the remote access trojan.

## Threat Actor Activities

- **Shahid Kaveh / IRGC (Iran)**: Linked by France to October 11–12 sabotage of refrigeration controllers at approximately 700 French retail sites, causing food losses and at least 15–20 fires; operates through personas including CyberAveng3rs and Cyber Isnaad Front; also targeted Schneider Electric industrial equipment at small hydroelectric installations.
- **Bitter (APT-C-08, Hazy Tiger, TA397, etc.)**: South Asian cyber espionage group deploying the PapRAT remote access trojan via LNK, VHDX, and WebDAV infection chains targeting organizations in South Asia; C2 at goodnfortunes[.]com, rivingtonclarks[.]com, and techtalkhelp[.]com.
- **BYOD ransomware gang**: Claimed encryption of Vanderbilt University databases and theft of student, employee, and research data; operates a data leak site and uses SESSION encrypted messaging for negotiation.
- **Unknown attackers (N-able Able2Shell)**: Disclosed more than 30 alleged N-central zero-days with proof-of-concept exploits enabling credential theft, administrator creation, and root command execution; N-able reported no observed active exploitation.
- **Unknown attacker (Qubole AWS abuse)**: Compromised AWS accounts belonging to multiple Qubole customers between October 14 and October 26 by abusing trusted cross-account AssumeRole access; stole secrets from Secrets Manager, SSM Parameter Store, Lambda environment variables, and S3 data.
- **Unknown threat actors (SSHole / TAC Agent)**: Exploitation attempts against OpenSSH SSHole with post-exploitation including deployment of the TAC Agent Python C2; observed recon, cloud metadata queries, and authorized_keys modification.
