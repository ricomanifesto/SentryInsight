# Exploitation Report

## Executive Summary

Multiple critical vulnerabilities across virtualization, web server, and application ecosystems are assessed in this reporting period. The VMware vCenter Server authentication bypass tracked as CVE-2026-123890 is linked to Chinese-linked threat actor Armory Castle, which exploited the flaw in zero-day attacks beginning in early September 2026 to gain administrative access to vCenter environments. Separately, two NGINX HTTP/2 vulnerabilities tracked as CVE-2026-123007 and CVE-2026-123633 could allow unauthenticated remote code execution, with exploitation status assessed as unknown based on the supplied evidence.

CVE-2026-90436 affecting Apache Axis is assessed as actively exploited, with Rapid7 detecting exploitation against Atlassian Confluence Data Center in a customer environment; the flaw is associated with cryptocurrency miner deployment alongside 4EverAble2Shell vulnerabilities. Additional critical flaws in PHP, Oracle, MySQL, PostgreSQL, ASUS management products, and Synology DSM require patching where updates are available, though exploitation status for these items remains unknown in the supplied sources.

Defenders should prioritize patching for all vulnerabilities with available fixes, apply mitigations where patches are unavailable, and review exposure to actively exploited flaws such as CVE-2026-90436. The report preserves negative and conflicting evidence for each finding, and no CVE is described as actively exploited unless the supplied evidence and status contract support that conclusion.

## Active Exploitation Details

### Apache Axis Unsafe Reflection Vulnerability (CVE-2026-90436)
- **Description**: An unsafe reflection vulnerability in Apache Axis that could allow an unauthenticated remote attacker to execute arbitrary code.
- **Impact**: Attackers can execute arbitrary code on vulnerable servers running affected Axis 1.x versions.
- **Status**: Exploitation status is active per the supplied assessment; Axis 1.x is end-of-life and remains unpatched, with migration to Apache Axis 2/Java recommended or use of a patched build from a July 12, 2026 commit.
- **Severity**: critical
- **Exploitation Status**: active
- **Action**: mitigate
- **CVE IDs**: CVE-2026-90436
- **Reporting**: [The Hacker News — CISA Warns of 4 Exploited Flaws Linked to Ransomware, Cryptomining, and LLMjacking Attacks](https://thehackernews.com/2026/11/cisa-warns-of-4-exploited-flaws-linked.html)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: None stated in supplied sources.
- **Recommended Actions**: CVE-2026-90436, which affects Axis 1.x versions, remains unpatched as Axis 1 has reached end-of-life (EoL) status. It's recommended to migrate to a different SOAP engine, such as Apache Axis 2/Java. Alternatively, users can use a build of Axis with the patch from a July 12, 2026, commit applied.

### VMware vCenter Directory Service Authentication Bypass (CVE-2026-123890)
- **Description**: An authentication bypass vulnerability in the VMware Directory Service in vCenter Server allowing unauthenticated attackers with network access to bypass authentication and gain unauthorized access.
- **Impact**: Attackers can obtain administrative access to vCenter, execute arbitrary commands, and acquire files including the data.mdb database, giving control over managed virtual machines.
- **Status**: Exploitation status is unknown per the supplied assessment despite reporting of Mandiant-documented attacks; Broadcom patched the vulnerability on November 19 in VMSA-2026-0009, and there are no official workarounds.
- **Severity**: critical
- **Exploitation Status**: unknown
- **Action**: patch
- **CVE IDs**: CVE-2026-123890
- **Reporting**: [Bleeping Computer — VMware patches vCenter zero-day exploited in attacks since September](https://www.bleepingcomputer.com/news/security/vmware-patches-vcenter-zero-day-exploited-in-attacks-since-september/), [The Hacker News — China-Linked Hackers Exploit Critical VMware vCenter Zero-Day to Gain Admin Access and Steal Data](https://thehackernews.com/2026/11/china-linked-hackers-exploit-critical.html)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: ESX itself is not affected; none of the five flaws in the advisory lets code run on an ESX host from inside a virtual machine.
- **Recommended Actions**: Broadcom patched the vulnerability on November 19 in VMSA-2026-0009; the company considers the vCenter vulnerability an emergency update, urging organizations to install the patches as soon as possible. Broadcom says there are no official workarounds for the vulnerabilities, although network restrictions and firewall controls can help reduce exposure.

### NGINX HTTP/2 Use-After-Free Vulnerability (CVE-2026-123633)
- **Description**: A use-after-free problem that affects NGINX when it accepts HTTP/2 connections and proxies requests to a backend, where low connection slots can cause the worker to close an active connection and free memory still in use by a request.
- **Impact**: Attackers can achieve unauthenticated remote code execution on vulnerable NGINX servers.
- **Status**: Exploitation status is unknown per the supplied assessment; Wiz demonstrated remote code execution but is not publicly releasing its PoC exploits. Fixes are available in NGINX Open Source 1.30.7 stable and 1.31.9 mainline, and NGINX Plus versions 37.0.8.1 or 37.3.0.1.
- **Severity**: unknown
- **Exploitation Status**: unknown
- **Action**: patch
- **CVE IDs**: CVE-2026-123633
- **Reporting**: [Bleeping Computer — Critical NGINX ‘NGINX2Root’ bugs let attackers hijack servers](https://www.bleepingcomputer.com/news/security/critical-nginx-nginx2root-bugs-let-attackers-hijack-servers/)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: None stated in supplied sources.
- **Recommended Actions**: For system administrators, it is recommended to upgrade immediately to the latest NGINX release, or temporarily disable HTTP/2 until an upgrade is possible. However, this mitigation only covers the two "nginx2root" flaws.
- **Vendor Links**: https://xint.io/blog/nginx2root-remote-code-execution; https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities; https://nginx.org/en/security_advisories.html

### NGINX HTTP/2 Flow-Control Memory Corruption Vulnerability (CVE-2026-123007)
- **Description**: A flow-control bug that can corrupt memory in an NGINX worker, impacting all versions from 1.31.8 down to 1.9.5 released in 2015.
- **Impact**: Attackers can achieve unauthenticated remote code execution on vulnerable NGINX servers hosting static files over HTTP/2 with TLS.
- **Status**: Exploitation status is unknown per the supplied assessment; Wiz demonstrated unauthenticated remote code execution, and Xint demoed root access by chaining with a separate Linux kernel flaw. Fixes are available in NGINX Open Source 1.30.7 stable and 1.31.9 mainline.

## Attack Vectors and Techniques

- **Authentication Bypass**: Unauthenticated network attacker bypasses VMware Directory Service authentication to establish an administrator session in vCenter
- **Vector**: Network access to vulnerable vCenter Server via DCE/RPC interface
- **Remote Code Execution via Memory Corruption**: Flow-control and use-after-free bugs in NGINX HTTP/2 workers allow unauthenticated code execution
- **Vector**: HTTP/2 connections to an NGINX listener, potentially with backend proxying
- **Unsafe Reflection**: Unauthenticated remote attacker executes arbitrary code through Apache Axis XML-RPC and SOAP APIs
- **Vector**: Crafted HTTP requests against Confluence Data Center with Remote API enabled
- **PHP Request Smuggling**: Attacker-controlled PHP code executed as the worker through reused backend connections to PHP-FPM
- **Vector**: Web servers with persistent FastCGI/PHP-FPM backend connections (nginx fastcgi_keep_conn, Apache mod_proxy_fcgi enablereuse, HAProxy, LSAPI)
- **Session TOCTOU**: Interrupted session write creates mixed session state leading to deserialization and code execution
- **Vector**: Multipart form upload with upload progress enabled, followed by session_start() call
- **Code Injection**: Crafted file-path or stream parameter during data import processing in REDCap public survey context
- **Vector**: HTTP requests to unintended controller routes requiring a valid public survey hash
- **Physical Lock Screen Bypass**: Physical access to locked Windows computer with Microsoft account recovery options and Narrator screen reader
- **Vector**: Local physical access to the lock screen

## Threat Actor Activities

- **Armory Castle (formerly UNC5221)**: Suspected Chinese state-sponsored cyber espionage group that exploited CVE-2026-123890 in VMware vCenter in early September 2026, using custom Golang tool BONESAW to create SSO administrator accounts, steal directory databases, extract SAML signing keys, and conduct Golden SAML attacks
- **Campaign**: Part of the same intrusion campaign that exploited BeyondTrust Remote Support zero-day CVE-2026-102764 since late August; attackers deployed SLIMSAVAGE, CAGEMATCH, BEARBONES, LAZYBONES, SAWSNAKE, and other malware to maintain persistence, exfiltrate data from ESXi hosts and Active Directory databases, and move laterally through virtualized environments
- **PHP2Shell Actor**: Israeli security firm Dream working with Palo Alto Networks identified an actor that obtained PAN-OS firmware, decrypted it, extracted PHP libraries, built memory profiles for nine software versions, and chained PHP2Shell (CVE-2026-109618 and CVE-2026-109619) with Linux kernel flaw CVE-2026-46300 to gain root on 25 systems across the U.S., Japan, Taiwan, and South Korea
- **Rapid7-Observed Activity**: Threat actors exploited CVE-2026-90436 against Atlassian Confluence Data Center to run shell commands, enumerate credentials and payment card numbers, perform AS-REP Roasting, and sign in to Microsoft 365 as an integration service actor
- **LLMjacking Actors**: Threat actors leveraged CVE-2026-40217 in LiteLLM to elevate inference keys into administrative credentials as part of attacks targeting financial services, retail, transportation, and technology organizations across multiple regions
- **Ransomware Actors**: CVE-2024-10441 in Synology DSM was exploited in ransomware attacks deploying C3RB3R ransomware on NAS devices
