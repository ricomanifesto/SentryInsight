# Exploitation Report

## Executive Summary

Critical exploitation activity has been observed across remote management, collaboration, and web application infrastructure. Threat actors have targeted ConnectWise ScreenConnect technician workstations through a now-patched client flaw that allows silent file transfer and execution, while CISA has flagged a high-severity Cisco BroadWorks vulnerability as actively exploited in attacks against telecommunications providers. A separate critical Cisco Expressway flaw involving hard-coded credentials and certificate validation bypass has been linked to root-level remote command execution on Internet-exposed clustered devices.

AI-assisted attack frameworks are accelerating intrusion timelines across financial, government, and technology sectors. CERT-In has warned of AI-driven campaigns targeting Indian banks and fintech firms, while frameworks such as ARTEX, CAIRN, and AntiFire are being used to rapidly convert patches into exploits and conduct autonomous intrusions. Microsoft has also remediated an Azure API Management Classic vulnerability that exposed stored API credentials, with Norwegian authorities linking the issue to attacks on energy sector organizations.

Additional critical flaws with assessed but unconfirmed exploitation include an insecure deserialization vulnerability in the defunct Idunno.AntiCsrf ASP.NET library, a server-side request forgery flaw in N-able Mail Assure, and multiple WHMCS SQL injection and code execution flaws. Patches or mitigations are available for most of these issues, though several affected-version details remain unspecified in the supplied sources.

### Idunno.AntiCsrf Insecure Deserialization Flaw
- **Description**: A critical insecure deserialization vulnerability in the Idunno.AntiCsrf ASP.NET IHttpModule allows remote code execution via a single unauthenticated HTTP POST request.
- **Impact**: Remote attackers can achieve arbitrary code execution in the context of the IIS worker process, resulting in complete compromise of the web application server.
- **Status**: No official patch available; exploitation status is potential. The open-source project is defunct and has not been updated since December 2008.
- **Severity**: critical
- **Exploitation Status**: potential
- **Action**: mitigate
- **CVE IDs**: CVE-2026-131914
- **Reporting**: [The Hacker News — Hackers Exploit Critical ASP.NET Anti-CSRF Library Flaw Allowing Unauthenticated RCE](https://thehackernews.com/2026/11/hackers-exploit-critical-aspnet-anti.html)
- **Affected Versions**: Unresolved from supplied sources.
- **Affected Versions Status**: unresolved
- **Exceptions**: None stated in supplied sources.
- **Recommended Actions**: Cybersecurity researchers have urged users to discontinue using a legacy ASP.NET anti-CSRF library named Idunno.AntiCsrf ("Idunno.AntiCsrf.dll") following the discovery of a critical vulnerability that has been exploited in the wild. The vulnerability, tracked as CVE-2026-131914, carries a CVSS score of 9.3 out of 10.0. The issue affects versions 0.9.1.0 and 0.9.1 Beta, and relates to an insecure deserialization vulnerability in the Idunno.AntiCsrf.AntiCsrfModule HTTP module. Idunno.AntiCsrf is a third-party ASP.NET IHttpModule designed to provide double-submit cookie Cross-Site Request Forgery (CSRF) protection for ASP.NET WebForms applications. The open-source project is currently defunct and has not been updated since December 2008. At its core, the problem stems from the fact that the module deserializes untrusted CSRF form token data using an unkeyed .NET System.Web.UI.ObjectStateFormatter instance without cryptographic MAC or signature verification when handling incoming HTTP POST requests to ASP.NET WebForms (System.Web.UI.Page) endpoints. This behavior, in turn, can allow a remote attacker to achieve arbitrary remote code execution (RCE). Google's Mandiant division has given the vulnerability a "High" exploitability assessment, adding that exploitation hinges only on a single HTTP POST request with no prior authentication or valid CSRF token. LDB, Genwei Jiang, Dhanesh Kizhakkinan, Brian Bahtiarian, and Lucas Kossack of Google Cloud and Mandiant Incident Response have been credited with discovering the flaw earlier this month. "A remote attacker can supply any non-empty value in the configured CSRF cookie alongside a Base64-encoded .NET ObjectStateFormatter gadget chain in the configured CSRF form field to execute arbitrary code in the context of the IIS worker process (w3wp.exe), resulting in complete compromise of the web application server," Google-owned Mandiant said in an alert issued last week. "Active exploitation in the wild has been observed." Google's threat intelligence team did not disclose any further details related to the activity. When reached for comment, Google told The Hacker News that it does not have anything to share at this time. In the absence of an official patch, organizations still using the library are advised to discontinue its use and replace it with an actively supported anti-CSRF alternative such as follows - System.Web.Helpers.AntiForgery ASP.NET WebForms Page.ViewStateUserKey combined with MAC-verified/encrypted ViewState on postback forms ASP.NET Core Anti-Request Forgery (IAntiforgery) "Audit all ASP.NET Web.config files and bin/ directories for references to Idunno.AntiCsrf or AntiCsrfModule, and review IIS logs for anomalous POST requests to .aspx endpoints returning HTTP 302 or HTTP 500 with elevated cs-bytes (where logged)," Google said. "Environments with evidence of exploitation should rotate all secrets stored in Web.config and applicationHost.config (including keys, encryption keys, and database credentials) and inspect webroots for unauthorized files."
- **Vendor Links**: https://github.com/mandiant/Vulnerability-Disclosures/blob/master/2026/MNDT-2026-0048.md

## Attack Vectors and Techniques

- **Guest-pushed file execution**: Malicious guest in ScreenConnect session pushes batch file to technician's host, which auto-executes without prompt; attacker registers unauthorized guest sessions using scripted emulator
- **Hard-coded credentials and certificate validation bypass**: Cisco Expressway flaw allows unauthenticated attackers to invoke RPC commands as root via database service
- **Insecure deserialization**: Idunno.AntiCsrf deserializes untrusted CSRF form token data using unkeyed ObjectStateFormatter without MAC verification via single HTTP POST request
- **Server-side request forgery**: N-able Mail Assure LDAP sync connection check has no destination restrictions, allowing connection to arbitrary internal hosts and ports
- **Unauthenticated SQL injection**: WHMCS shopping cart accessible without login, exposing customer records and admin password hashes
- **Authenticated SQL injection**: WHMCS Client Area flaw requires logged-in client with View & Manage Contacts permission to access other customers' data
- **Path traversal**: MONAI Label allows unauthenticated remote attacker to write arbitrary files outside intended datastore directory, potentially resulting in remote code execution
- **Code injection via parser definitions**: binary-parser inserts unvalidated string options directly into generated JavaScript code during parser compilation
- **Authentication bypass**: VMware Directory Service flaw allows unauthorized access to vCenter Server
- **AI-driven agentic intrusion**: Frameworks such as ARTEX, CAIRN, AntiFire, and exploit_agent automate reconnaissance, exploit generation from patches, credential harvesting, and lateral movement with minimal human involvement
