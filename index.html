Executive Summary

Multiple critical vulnerabilities are currently affecting widely deployed infrastructure, including NGINX web servers, Oracle Java runtimes, and Perforce Puppet configuration management systems. A decade-old NGINX HTTP/2 flaw tracked as CVE-2026-123007 allows unauthenticated remote code execution when HTTP/2 is enabled, with proof-of-concept code publicly available though no confirmed exploitation has been reported. Separately, the Java4Shell flaw (CVE-2026-114938) in the Java Base64 decoder permits unauthenticated remote code execution on affected x86-64 systems; CISA has urged immediate patching while noting no evidence of wild exploitation as of publication.

Active exploitation activity has also been observed in the threat landscape. CISA added CVE-2026-115731, a Puppet deserialization vulnerability, to its Known Exploited Vulnerabilities catalog citing reports of active exploitation, though the supplied evidence assessment treats exploitation status as unknown. F5 disclosed six critical BIG-IP flaws that can crash traffic management components and may allow remote code execution in specific configurations, with engineering hotfixes available but no workarounds. Concurrently, threat actors including the EggStreme operators, Cold Relic, and Earth Alux are conducting targeted campaigns against government entities in Southeast Asia, leveraging rebuilt malware, cloud identity abuse, and vulnerable Exchange servers.

Supply chain and client-side risks round out the reporting period. Microsoft's agent-framework PyPI package was compromised with malicious versions 1.26.1 and 1.26.2 deploying a credential stealer targeting cloud identities and environment variables. An AMD TPM lockout bypass (CVE-2026-43613) allows short Windows Hello and BitLocker PINs to be guessed within hours or days through physical access and flash chip manipulation. Defenders should prioritize patching where fixes are available, apply mitigations where they are not, and monitor for the threat actor techniques described below.

CriticalExploitation unknownPatchCVE-2026-123007#

Reporting
  • The Hacker News — 10-Year-Old NGINX HTTP/2 Flaw Lets Unauthenticated Attackers Execute Code on Servers · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: nginx.org, my.f5.com

Earlier reporting
  • CVE-2026-123007. First report of this CVE in the retained archive.
  • Description: A decade-old integer underflow flaw in NGINX's HTTP/2 support, present since version 1.9.5, allows unauthenticated attackers to execute code on servers with HTTP/2 enabled by sending specially crafted HTTP/2 requests.
  • Impact: Attackers can achieve remote code execution with the permissions of an NGINX worker process; privilege escalation to root may be possible through a separate Linux kernel SCTP bug, including in Docker container environments.
  • Status: Exploitation status is unknown. Neither the vendor nor Wiz and Rapid7 researchers have reported attacks exploiting the flaw, and CISA's Known Exploited Vulnerabilities catalog did not list it as of publication. Fixed versions 1.31.9 and 1.30.7 are available.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: NGINX Open Source 1.31.9 and 1.30.7 are fixed; NGINX Plus 37.3.0.1 and 37.0.8.1 fix four of the five flaws, with CVE-2026-123633 fixed in earlier builds 37.2.0.1 and 37.0.7.1; NGINX Plus R34 to R36 has no fix listed
  • Recommended Actions: Upgrade to NGINX Open Source 1.31.9 or 1.30.7, or the applicable fixed NGINX Plus build; after upgrading, restart NGINX fully or use its live binary upgrade because a reload alone leaves the old executable running. As a temporary mitigation, turn off HTTP/2 by removing http2 from listen directives (set http2 off on 1.25.1 and later, or remove http2 from listen 443 ssl http2 on 1.9.5 through 1.25.0), then restart NGINX and confirm with openssl s_client -alpn h2 that HTTP/2 is no longer accepted. Hosts not using SCTP should block the sctp kernel module from loading (e.g., install sctp /bin/false in /etc/modprobe.d/) pending a kernel fix for the SCTP privilege escalation path.

  • The Hacker News — CISA Urges Immediate Patching of Java4Shell Flaw That Could Allow Remote Code Execution · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: oracle.com, openjdk.org, cisa.gov

Earlier reporting
  • CVE-2026-114938. First report of this CVE in the retained archive.
  • Description: An out-of-bounds write in the AVX-512 VBMI-accelerated Java Base64 decoder on x86-64 systems allows unauthenticated remote code execution when malformed Base64 input ending in extra padding characters is processed before authentication checks.
  • Impact: Attackers without an account can execute arbitrary code on vulnerable Java applications including Keycloak, Atlassian Jira, Atlassian Confluence, JFrog Artifactory, Jenkins, and PingFederate under default settings, with login required for Apache Kafka Broker, Apache Solr, Elasticsearch, Gerrit, and Spinnaker.
  • Status: Exploitation status is not_observed. CISA stated there is no evidence the vulnerability has been exploited in the wild as of writing, although watchTowr reported observing initial reconnaissance and blind exploitation attempts against its sensors.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Standard Java 8 and Java 11 do not contain the vulnerable code, though the Java SE 8 Performance Pack build 8u511b33-perf is affected; ARM64 chips do not run the vulnerable AVX-512 VBMI decoder path
  • Recommended Actions: Apply patches from Oracle, OpenJDK, Amazon Corretto, Azul Zulu, or other vendors; fixed builds include 17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1, and corresponding vendor releases. If immediate patching is not feasible, start the JVM with -XX:-UseBASE64Intrinsics to turn off only the faster Base64 code, or -XX:UseAVX=2 to turn off AVX-512 entirely on x86-64 servers only. Restrict and validate Base64 input at the application boundary, enforce input-size limits, and limit unauthenticated access where possible. Restart Java services and rebuild and redeploy container images after updating.

Earlier reporting
  • CVE-2026-115731. Reported on 1 earlier report date since November 18: Nov 18. This finding and the November 18 finding cite the same source. The November 18 finding had the same labels.
  • Description: A deserialization of untrusted data vulnerability in Puppet's report-processing code allows a client with any CA-signed agent certificate to execute arbitrary code on the Puppet Server as the service user by submitting a report containing a crafted rich-data type through a PUT request; if the certificate authority automatically signs requests without strong verification, an unauthenticated network attacker can obtain a valid certificate and exploit the vulnerability.
  • Impact: Remote code execution on a Puppet server can allow attackers to grab CA signing keys, impersonate other hosts, deploy ransomware, exfiltrate data, and move laterally across networks managed by Puppet.
  • Status: Exploitation status is unknown per the supplied evidence assessment. CISA added the flaw to its Known Exploited Vulnerabilities catalog citing reports of active exploitation, but no details on weaponization in the wild were provided as of publication. Fixes were released November 3, 2026.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Puppet Enterprise 2026.0.1 (Puppet Core 9.1.3), Puppet Enterprise 2025.12.1 (Puppet Core 8.22.2), Puppet Enterprise 2023.8.13 (Puppet Core 8.22.2), Puppet Core 9.1.3, Puppet Core 8.22.2, OpenVox Agent 9.3.0 and 8.32.0, OpenVox Server 9.2.0 and 8.18.0 are resolved
  • Recommended Actions: Apply the fixed versions listed above; Federal Civilian Executive Branch agencies are advised to apply fixes by December 1, 2026 under Binding Operational Directive 26-04. Ensure certificate authority signing requires strong verification to prevent unauthenticated certificate acquisition.

MediumExploitation unknownMitigateCVE-2026-43613#

Reporting
  • The Hacker News — New Attack Bypasses TPM Lockout to Crack Windows Hello and BitLocker PINs in Days, Not Years · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: amd.com, intel.com

Earlier reporting
  • CVE-2026-43613. First report of this CVE in the retained archive.
  • Description: A flaw in AMD processor firmware allows the TPM lockout counter for Windows Hello and BitLocker PINs to be reset by writing an old saved state back to the mainboard flash chip, enabling unlimited PIN guessing attempts on systems with firmware TPM and certain flash configurations.
  • Impact: Short PINs become practical to brute-force; a four-digit Windows Hello PIN can be found in a worst case of 40 hours (versus 69 days with lockout working), and a six-digit BitLocker PIN in 20 days (versus 19 years with lockout working).
  • Status: Exploitation status is unknown. AMD confirmed the firmware flaw and plans fixes between November 2026 and February 2027; neither the paper nor vendor notices describe attacks outside the lab.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Three Intel systems in testing detected the write-back attack; AMD firmware bulletin does not cover AMD PCs without RPMC flash
  • Recommended Actions: Add at least two digits to Windows Hello and BitLocker PINs; raise the Minimum PIN length policy for Windows Hello for Business and the Configure minimum PIN length for startup policy for BitLocker; install AMD firmware updates when available for affected Ryzen, Ryzen AI, Ryzen Threadripper, Athlon, and EPYC chips; keep PCs under physical control and watch for signs of tampering until fixes are available.

Vendor guidance: postgresql.org

Earlier reporting
  • CVE-2026-116331. First report of this CVE in the retained archive.
  • Description: A type-confusion bug in PostgreSQL allows an account that can create database objects to run code as the operating system user running the database, without touching application data.
  • Impact: Code execution on the PostgreSQL server host with the privileges of the database service account.
  • Status: Exploitation status is unknown. Fixed November 12 in a security advisory; no sign of real-world exploitation was reported.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Fixed releases 18.7, 17.12, 16.16, 15.20, 14.25 are not affected
  • Recommended Actions: Install the PostgreSQL security update from November 12; review account privileges and restrict temporary object creation rights where unnecessary.

Affected Systems and Products

  • NGINX Open Source and NGINX Plus: Versions 1.9.5 through 1.31.8 on open source; NGINX Plus 37.x releases before fixed builds and R34 to R36; affected platforms include any server with HTTP/2 enabled via listen directive with http2 or http2 on, including Docker containers on AWS, GCP, and Azure
  • Oracle Java / OpenJDK distributions: Java 17.0.6 and later, Java 21, 25, and 27 on x86-64 Intel and AMD chips supporting AVX-512 VBMI; includes Oracle Java SE, Amazon Corretto, Azul Zulu, SAP SapMachine, GraalVM, and Red Hat builds of OpenJDK; Java 8 Performance Pack build 8u511b33-perf also affected
  • Perforce Puppet and OpenVox: Puppet Enterprise 2026.0.0 before 2026.0.1, 2025.0.0 before 2025.12.1, 2023.8.0 before 2023.8.13; Puppet Core 9.0.0 before 9.1.3 and 8.x before 8.22.2; OpenVox Agent and Server implementations
  • AMD-based PCs: Systems with firmware TPM using RPMC flash chips, including Ryzen, Ryzen AI, Ryzen Threadripper, Athlon, and EPYC platforms; Windows Hello and BitLocker PIN protections affected
  • F5 BIG-IP: BIG-IP APM, PEM, DNS, and all modules; BIG-IP Next for Kubernetes and BIG-IP CNF in specific versions; virtual servers with iRules using particular commands or APM policies with specific agents
  • MySQL Server and Cluster: Versions 26.7.0 to 26.7.1
  • PostgreSQL: Versions before 18.7, 17.12, 16.16, 15.20, 14.25

Attack Vectors and Techniques

  • HTTP/2 Request Smuggling and Integer Underflow: Maliciously crafted HTTP/2 traffic triggers an integer underflow in NGINX's HTTP/2 implementation, leading to memory corruption and remote code execution; requires HTTP/2 to be enabled on the listener
  • Malformed Base64 Input: Base64 strings ending with extra = characters are processed by the AVX-512 VBMI-accelerated decoder before authentication, causing an out-of-bounds write that can be chained to arbitrary code execution; reachable via HTTP Basic headers, SAML artifacts, CSRF tokens, and other pre-auth decoding paths
  • Deserialization of Untrusted Data: Crafted rich-data types submitted through PUT requests to Puppet's report-processing endpoint are deserialized without adequate validation, allowing arbitrary code execution on the Puppet Server
  • TPM Lockout Counter Reset: Physical access to the mainboard flash chip allows copying and restoring old TPM state to reset incorrect PIN guess counters, enabling brute-force attacks on Windows Hello and BitLocker PINs; voltage glitching of Winbond RPMC chips can extract signing keys to forge counter values
  • DLL Sideloading: Malicious DLLs placed under trusted system library names are loaded by legitimate applications, executing payloads without disk-based detection; used by EggStreme and Mustang Panda malware frameworks
  • Cloud Identity Abuse: Stolen Super Admin credentials and MFA push fatigue are used to register attacker-controlled devices and passkeys, then Google Takeout and OAuth are abused to exfiltrate cloud storage and email data
  • PyPI Supply Chain Compromise: Malicious .pth files in compromised Python packages execute credential stealers on every interpreter startup via site-packages hooks, exfiltrating environment variables, credential files, and cloud identity tokens to attacker-controlled webhooks

Threat Actor Activities

  • EggStreme operators (suspected Chinese APT): Rebuilt malware toolkit targeting Philippine government organizations since late October 2026; uses DLL sideloading, passive beacon-less variants, campaign-specific certificate authorities, and VBScript payloads launched over SMB from unmanaged systems; some components previously used by cluster CL-STA-1048 between March and September 2025
  • Mustang Panda: Targeted Philippine government officials with ASEAN Summit lures impersonating Laos-Philippines bilateral meeting agendas to deliver PlugX remote-access malware via DLL sideloading
  • Earth Alux (Ink Dragon, Jewelbug, REF7707, UAT-11587, TGR-STA-0049): China-nexus actor targeting Southeast Asian government entities since at least July 2025; exploits vulnerable unpatched Microsoft Exchange servers to deploy web shells (ASPXSpy, Godzilla) and deploys PerfectPioneer RAT and KUKURAT modular implants using HTTP/3 for C2 communication
  • Cold Relic (COLDRIVER, UNC4057, Callisto, Gossamer Bear, Star Blizzard): Russia-linked espionage group weaponizing cloud compromises to pivot to second organizations; uses stolen Super Admin credentials, MFA device registration, passkeys, and Google Takeout to exfiltrate data, then impersonates victims in social engineering campaigns against their professional networks
  • Scattered Spider (0ktapus, Octo Tempest, UNC3944, Muddled Libra): Financially motivated cybercrime collective; leader sentenced to six years in prison for SIM swapping and phishing attacks stealing over $11.6 million in cryptocurrency; partners with BlackCat/AlphV, Qilin, and RansomHub ransomware operations
  • watchTowr-observed actors: Conducting internet-wide scanning and blind exploitation attempts against Java4Shell-vulnerable systems using "java4shell-recon" User-Agents against honeypot sensors
