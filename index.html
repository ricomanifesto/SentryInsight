Exploitation ReportNovember 13, 2026

Executive Summary

Recent exploitation activity centers on remote management and monitoring infrastructure. ConnectWise ScreenConnect deployments were targeted by the SCKit malware toolkit, which attempts to exploit the patched CVE-2026-84869 flaw to hijack authenticated technician sessions and propagate across managed environments. Blackpoint Cyber and Huntress confirmed the exploit payload is blocked by the existing vendor patch, and there is no evidence of successful propagation to technician workstations or patch bypass in the current campaign; however, CVE-2026-84869 remains in CISA's Known Exploited Vulnerabilities catalog based on prior exploitation. Separately, N-able N-central servers were targeted through the 4EverAble2Shell exploit chain combining CVE-2026-90436 with a privilege escalation weakness; researchers observed exploitation attempts and cryptocurrency miner deployment on at least 21 production servers, though the scoped evidence assessment records exploitation status as not_observed.

Enterprise applications and infrastructure also received critical patches. PTC addressed CVE-2026-126325, a remote code execution flaw in Windchill and FlexPLM involving deserialization of untrusted data, following prior active exploitation of CVE-2026-12569 by Cl0p ransomware affiliates. Red Hat disclosed critical Quay registry flaws CVE-2026-123710 and CVE-2026-110697 allowing unauthenticated or low-privileged readers to access and overwrite private container images across repositories. The Apache Software Foundation patched CVE-2026-119618, a critical HTTP/2 remote code execution vulnerability in mod_http2 affecting versions 2.4.55 through 2.4.70, though no public exploitation was reported at disclosure.

Additional activity includes the SignDrop Windows zero-day targeting the CLFS driver authentication feature for SYSTEM privilege escalation with no assigned CVE or patch, and Operation Endgame law enforcement seizures of Gootloader, CastleRAT, and StealC infrastructure across nine countries. GSocket abuse was observed on Linux web and hosting servers for stealthy persistent access after initial compromise, frequently paired with attempts to exploit the Dirty Frag kernel flaw CVE-2026-43284. Multiple other vulnerabilities in Node.js, AMD Turin processors, Citrix NetScaler, and Microsoft components were patched or disclosed with exploitation status assessed as unknown based on the supplied evidence.

Earlier reporting
  • CVE-2026-84869. First report of this CVE in the retained archive.
  • Description: CVE-2026-84869 is an improper privilege management and missing authorization vulnerability in ConnectWise ScreenConnect that could allow an attacker to perform file transfer and execute code through an active remote session without authorization or host confirmation. The SCKit malware toolkit attempts a guest-to-host file execution technique associated with this flaw by replacing the legitimate ScreenConnect Guest process and sending malicious payloads back to connecting technicians. The vulnerability was patched in ScreenConnect version 26.6.5.
  • Impact: Successful exploitation could allow attackers to deploy additional software under the NT AUTHORITY\SYSTEM context on technician workstations, recover authenticated ScreenConnect browser sessions (.ASPXAUTH cookies), and use existing management permissions to distribute commands across additional customer endpoints. Attackers could move from a single compromised endpoint into broader customer environments through the same remote support infrastructure.
  • Status: Patched. Testing against a fully patched ScreenConnect client successfully prevents execution of the exploit payload. No evidence of successful propagation to technician workstations or bypass of the vendor patch was observed as of writing.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Fully patched ScreenConnect clients prevent execution of the exploit payload.
  • Recommended Actions: Patch ScreenConnect clients as soon as possible; investigate management relationships, rogue Access installations, administrative command history, technician workstations, and browser sessions; disable affected third-party extensions where possible; avoid interactive ScreenConnect sessions with potentially infected endpoints and use separate security tools for investigation; apply tighter session validation and additional authentication for bulk administrative actions.

CriticalExploitation unknownPatchCVE-2026-123710#

Reporting
  • The Hacker News — Critical Red Hat Quay Flaw Lets Attackers Read and Overwrite All Private Container Images in a Registry · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: access.redhat.com, access.redhat.com (2), bugzilla.redhat.com

Earlier reporting
  • CVE-2026-123710. First report of this CVE in the retained archive.
  • Description: CVE-2026-123710 (CVSS 9.8) is a critical flaw in Red Hat Quay that allows an attacker who can access a Quay registry to read and overwrite private container images in every repository. Quay uses trusted keys to sign access tokens for image pushes and pulls. The flaw lets an attacker add their own key to the keys Quay trusts, with no expiry date. Quay then accepts tokens signed with that key for any repository. The logic behind this flaw has been in Quay since its first public commit.
  • Impact: Attackers can retrieve private images and any secrets or credentials stored within them, push or overwrite images (with changes propagating to every system that pulls those images), and delete trusted keys so normal pushes and pulls fail. Anonymous access is enabled by default, requiring no account; when disabled, any valid account can still exploit the flaw. A planted key survives restarts until removed and persists across password resets and robot token changes.
  • Status: Fixed builds released for eight Quay 3 branches. Red Hat lists every version of Quay 3 and Quay 5 as affected. The CVE entry showed every Quay package as affected with no fix listed at time of checking, despite advisories listing the flaw.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Quay.io is already fixed for related issues (applies to CVE-2026-110697 context); turning off anonymous access does not protect against CVE-2026-123710.
  • Recommended Actions: At the proxy or load balancer, block the /keys endpoint for everything except trusted internal components; search audit logs for service_key_rotate and service_key_delete events where expiration_date is null; remove unrecognized approved service keys; install the fixed release; limit who can create organizations or namespaces containing an underscore; rotate robot tokens for namespaces matching underscore patterns; watch for anomalous pulls or pushes.

CriticalExploitation unknownPatchCVE-2026-110697#

Reporting
  • The Hacker News — Critical Red Hat Quay Flaw Lets Attackers Read and Overwrite All Private Container Images in a Registry · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: access.redhat.com, github.com

Earlier reporting
  • CVE-2026-110697. First report of this CVE in the retained archive.
  • Description: CVE-2026-110697 (CVSS 9.9) is a second critical flaw disclosed alongside CVE-2026-123710. It lets a Quay user who can create a namespace steal other tenants' robot account tokens and use them to read, push, or overwrite those tenants' images. The flaw is in code that lists robot accounts; it builds an SQL LIKE pattern from the namespace name without escaping wildcard characters, so an underscore in a namespace name can match another tenant's namespace and return its robot accounts with decrypted tokens. No elevated privileges are required.
  • Impact: Attackers can read, push, or overwrite other tenants' private container images and steal robot account tokens with decrypted credentials. Deleting the attacker's namespace deletes corresponding robot accounts, cutting off systems that rely on them. Where Quay is the integrated registry for OpenShift, stolen robot credentials can inject malicious images into CI/CD pipelines.
  • Status: Fixed builds released for eight Quay 3 branches. The company's CVE page names the same eight releases as fixed and calls updating the only complete fix. Quay.io is already fixed. None of the eight advisories list CVE-2026-110697.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Quay.io is already fixed.
  • Recommended Actions: Install the fixed release (only complete fix); limit who can create organizations or namespaces containing an underscore; rotate robot tokens for any namespace that matches an underscore namespace; watch for pulls or pushes that do not fit normal robot use.

Attack Vectors and Techniques

  • Guest-to-Host File Execution: SCKit RelayTrap component replaces the legitimate ScreenConnect Guest process and attempts to exploit CVE-2026-84869 to send a malicious file from an infected customer endpoint to a technician's workstation for execution, reversing the normal file-transfer direction.
  • Authenticated Session Hijacking: SCKit steals ScreenConnect authentication cookies (.ASPXAUTH) from browser data and process memory on technician workstations to hijack management sessions without credentials or MFA challenges.
  • Unauthenticated Command Execution via Blank Access Key: RMM+ versions 1.0.31 and 1.0.32 accept a blank shared access key when not configured, allowing attackers to issue remote commands through ScreenConnect without normal authentication or MFA.
  • Apache Axis SOAP Fault Class Instantiation: CVE-2026-90436 exploit chain uses unsafe class instantiation during SOAP fault processing to execute commands as the nable service account, followed by N-central privilege escalation (setLDFileOwner symbolic link abuse and serverControl) to obtain root.
  • Apache HTTP Server mod_http2 Race Condition: Concurrent threads sharing resources in assign_headers() cause heap corruption that can be leveraged for remote code execution with web server process privileges.
  • Quay Trusted Key Injection: Attacker adds their own signing key to Quay's trusted key store with no expiry; Quay accepts tokens signed with that key for any repository, enabling private image access and push/overwrite.
  • Quay SQL LIKE Namespace Traversal: Unescaped wildcard characters in namespace names allow SQL LIKE pattern matching to return other tenants' robot accounts with decrypted tokens.
  • GSocket Outbound Relay Persistence: Compromised Linux servers and attackers both connect outbound to the Global Socket Relay Network, eliminating the need for inbound listeners and bypassing IP/domain-based access controls. GSocket is disguised as kernel threads with persistence via cron, systemd, and shell startup files.
  • CLFS Authentication File Creation Abuse (SignDrop): A privileged process (e.g., Windows Defender) opens a prepared CLFS log, causing the driver to create a companion .cnpf file with SYSTEM privileges that the attacker can redirect via object manager symbolic links and write to, enabling SYSTEM shell access.
  • Google Calendar Reverse Proxy Session Capture: Attackers use live reverse proxies in front of Google sign-in pages, capturing passwords and second factors in real time through legitimate Google redirector URLs and Cloudflare Turnstile challenges.
  • Apache Axis Unauthenticated Exploit Chain: CVE-2026-90436 exploited with no authentication required to achieve initial code execution as the nable service account on N-central servers.
