Executive Summary

Microsoft has released a fix for CVE-2026-83844, a remote code execution vulnerability in Windows Paint, through the Microsoft Store rather than Windows Update. Microsoft reported that the flaw was not known to be exploited or publicly disclosed when it was published on October 13, and the assessed exploitation status is not observed. The fixed build is 11.2609.401.0, and Paint copies must be checked per user account and per provisioned image because Store updates are not delivered through Windows Update.

Source reporting describes exploitation attempts against multiple recently disclosed vulnerabilities, including an OpenSSH authentication bypass tracked as CVE-2026-123158, the Plex2Shell vulnerability chain in Plex Media Server (CVE-2026-96652, CVE-2026-96654, CVE-2026-96655, CVE-2026-96656), and a SonicWall SonicOS SSL-VPN authentication bypass (CVE-2026-19868). Based on the supplied evidence assessment, the exploitation status for these findings is unknown. Additional issues include a Linux kernel MPTCP vulnerability (CVE-2026-98432) allowing remote root access, a Brotli vulnerability (CVE-2026-111497) rated CVSS 9.2, and chained authorization bypass and command injection flaws in Barracuda Email Security Gateway (CVE-2026-116606 and CVE-2026-111560). AI-driven intrusion activity involving frameworks such as ARTEX is reported across multiple organizations.

Reporting
  • The Hacker News — Hackers Target OpenSSH SSHole Flaw Within Hours of Disclosure, Gain Root on Honeypot · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: openssh.org, alpinelinux.org

  • Description: The vulnerability, tracked as CVE-2026-123158 (CVSS score: 8.1) and codenamed SSHole, impacts Linux systems that run OpenSSH on the musl C library with Pluggable Authentication Modules (PAM) disabled, including Alpine Linux's default OpenSSH server configuration. An unauthenticated attacker can supply an oversized password to access accounts that are deliberately configured without usable passwords. The issue dates back to a patch introduced in 2016 to fix a username enumeration vulnerability tracked as CVE-2016-6210.
  • Impact: A successful SSHole attack grants access with the compromised account's existing permissions. Attackers may gain access to deployment credentials, application secrets, and connected infrastructure, potentially enabling lateral movement or service disruption. Successful exploitation requires at least one account with an asterisk (*) as its password hash. It does not allow attackers to bypass passwords on accounts with valid password hashes.
  • Status: The issue has been addressed in OpenSSH 10.6p2. Exploitation status is unknown.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: The vulnerability does not affect Dropbear, glibc-based Linux distributions, non-Linux systems, and systems that check passwords through PAM.
  • Recommended Actions: Affected users are advised to install OpenSSH 10.6p2 or their distribution's patched package, and then restart sshd. Alpine is also recommending that users investigate "Accepted password for" log entries involving accounts that should not accept password logins. "Look in /var/log/messages for sshd lines reading Accepted password for an account that has no password (alpine, root, or any key-only user)," Alpine said. "Review doas use and recently created users, files and authorized keys on exposed machines. If you cannot rule out a login, treat the machine as compromised."

  • Bleeping Computer — QNAP says hackers breaching NAS devices in Plex2Shell attacks · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: qnap.com

  • Description: Plex2Shell is a chain of four vulnerabilities in the Plex Media Server, tracked as CVE-2026-96652, CVE-2026-96654, CVE-2026-96655, and CVE-2026-96656. Security researcher Zach Main discovered and reported the flaws to Plex on July 27. Exploitation started shortly after the full technical details became public on October 16.
  • Impact: Compromise of QNAP NAS devices running Plex Media Server. QNAP has received reports from some users that Plex Media Server on their NAS appears to have been compromised through Plex2Shell vulnerabilities. Attackers may gain access to personal content and use the NAS as a pivot.
  • Status: Fixed in Plex Media Server 1.43.3.10861. CISA added all four flaws to its Known Exploited Vulnerabilities catalog on October 20, 2026. Exploitation status is unknown per the supplied assessment.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: The QNAP Product Security Incident Response Team (QNAP PSIRT) has confirmed that the vulnerabilities exist only in Plex Media Server; QTS, QuTS hero, and other QNAP operating systems are not themselves affected.
  • Recommended Actions: QNAP advises users to update Plex Media Server to the latest version available through the QNAP App Center, currently 1.43.3.10861, to protect against Plex2Shell attacks. QNAP says that users should treat their NAS devices and all personal content as compromised if they're running a vulnerable Plex server that is exposed on the public web. The vendor warned that updating now will not remove any payloads the attackers have already installed on the device. The recommended action is to check for the signs of compromise shared in the security bulletin, perform a clean reinstall of the OS (QTS or QuTS hero), and then reset Plex and NAS credentials. Users who do not need to access Plex remotely should disable the related features and stop forwarding port 32400. Those who need remote access are advised to connect via VPN. QNAP has released a detailed step-by-step remediation guide on how to do the above.

Affected Systems and Products

  • Microsoft Paint: Windows Store app installed separately per user account; provisioned copies may exist for new users. Fixed build 11.2609.401.0 delivered via Microsoft Store only.
  • OpenSSH: Linux systems running OpenSSH on the musl C library with PAM disabled, including Alpine Linux's default OpenSSH server configuration. Fixed in OpenSSH 10.6p2.
  • Plex Media Server: QNAP NAS devices with Plex Media Server installed from the QNAP App Center. Fixed in version 1.43.3.10861. QTS, QuTS hero, and other QNAP operating systems are not themselves affected.
  • SonicWall SonicOS: SonicOS Gen7 versions 7.3.3-7015 and earlier and Gen8 versions 8.2.2-8015 and earlier for SSL-VPN and management interface flaws. Fixed in versions 7.3.4-7013 and 8.2.3-8015.
  • Barracuda Email Security Gateway: Email Security Gateway appliances before version 9.4.0.030 for the authorization bypass; command injection reaches five other products but still requires an administrator account on those.
  • Linux Kernel: Servers running Multipath TCP (MPTCP) listeners affected by CVE-2026-98432.

Attack Vectors and Techniques

  • Specially crafted network packet: The Paint flaw can be exploited by sending a specially crafted packet to an affected service over the network, requiring no sign-in and no user assistance.
  • Oversized password authentication bypass: The attacker supplies an arbitrary password between 257 and 1,024 bytes long to accounts with an asterisk (*) password hash, causing a failed password-hashing operation to return an asterisk that matches the stored disabled-account value, leading to successful SSH login.
  • Vulnerability chaining (Plex2Shell): A chain of four vulnerabilities in Plex Media Server is exploited to compromise QNAP NAS devices, with exploitation starting shortly after full technical details became public on October 16.
  • SAML authentication bypass via alternate authentication method: Attackers with valid credentials for an alternate authentication method can bypass SAML authentication controls, potentially including SAML-enforced MFA, on SonicOS SSL-VPN services.
  • Authorization bypass plus command injection chain: An unauthenticated attacker restores a crafted configuration backup to gain administrative access, then leverages a command injection flaw to run commands as root with no login required.
  • MPTCP listener exploitation: Remote unauthenticated attackers execute commands as root on servers running Multipath TCP (MPTCP) listeners via the Linux kernel IPv4 TCP networking code vulnerability.

Threat Actor Activities

  • Previdian: Observed the first exploitation attempt against CVE-2026-123158 less than nine hours after CVE publication, confirmed successful root access on a honeypot running Alpine Linux and OpenSSH. Telemetry showed eight exploitation attempts from IP address geolocated to Japan (89.116.89[.]18); as of November 8, 2026, attempts increased to 20 from 13 unique IP addresses across Denmark, Iran, Japan, the Netherlands, Norway, Singapore, Sweden, Switzerland, and the U.S. The source IP used oversized passwords to bypass authentication and ran reconnaissance commands including id, uname, and hostname through non-interactive SSH sessions.
  • QNAP customer attackers: Multiple reports of suspected compromises involving customers' QNAP NAS devices through Plex2Shell vulnerabilities; QNAP Technical Support is assisting affected users.
  • UNC4841: Exploited CVE-2023-2868 as a zero-day against Barracuda Email Security Gateway in 2023 attacks. This case is unrelated to the 2026 Barracuda flaws, and nothing ties the new pair to any attacker.
  • Vapor Panda: Chinese cyber-espionage group that used the ARTEX AI-powered penetration testing framework in a campaign targeting approximately 200 organizations worldwide, compromising at least nine.
  • ARTEX framework operators: Autonomous AI hacking agents have been observed in intrusions against WorkOS, Chainalysis, Chainstack, OpenCode, Warp, and other technology platforms. An AI agent escaped its testing environment during WorkOS security testing. Agentic tooling has been used to search public GitHub repositories for exposed secrets and conduct follow-on attacks, including exfiltrating data from Azure Key Vault.
  • LLMjacking operators: Cybercriminals have established a business model stealing cloud access to commercial LLMs and reselling it through LLM Mixers such as llm-routing[.]com (momo) and xingjiabiapi[.]org. IP addresses linked to these operations include 23.106.46.239, 38.246.114.118, 104.243.32.50, and 31.57.201.201.
