Executive Summary

Recent vulnerability reporting highlights multiple patched flaws with assessed exploitation potential across Linux, Apple, and network infrastructure. A critical OpenSSH authentication bypass affecting musl-based Linux systems—including Alpine Linux, OpenWrt, Buildroot, and Yocto—is associated with CVE-2016-6210 and patched in OpenSSH 10.6p2. The flaw allows login to password-disabled accounts using oversized passwords under specific configurations. Apple's CVE-2024-27834 (CVSS 5.5) has been added to CISA's Known Exploited Vulnerabilities catalog following reported active exploitation, though supplied evidence assesses exploitation as potential.

Zyxel GS1900 switches face CVE-2026-107441, an out-of-bounds write zero-day that bypasses an earlier patch for CVE-2026-7273 and permits unauthenticated root command execution; patches were issued in October 2026. Nearly 1,000 switches were previously compromised in attacks linked to the Kapibala/Red Heron cluster. Docker Sandboxes CVE-2026-103916 and Apache OFBiz CVE-2026-109928/CVE-2026-68524 have patches available, while Debian/Ubuntu APT flaw CVE-2026-109518 also has fixed releases.

Threat activity includes APT29 watering-hole campaigns targeting mobile users and Zyxel switch intrusions attributed to Chinese-speaking actors. Defenders should prioritize patching OpenSSH, Apple, Zyxel, Docker Sandboxes, Apache OFBiz, and APT components while monitoring for compromise indicators where exploitation status remains unknown or potential rather than confirmed.

Reporting
  • Bleeping Computer — OpenSSH flaw lets attackers log into password-disabled Linux accounts · Digest context
  • The Hacker News — OpenSSH Issues Emergency Fix for Flaw Letting Long Passwords Bypass SSH Auth on Alpine Linux · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: sshhole.com, alpinelinux.org, openssh.org

  • Description: A newly disclosed flaw involving OpenSSH and musl, dubbed "*sshole," allows attackers to log in to certain Alpine Linux and other musl-based Linux accounts configured to block password authentication by entering an oversized password. The flaw stems from a 2016 OpenSSH change addressing CVE-2016-6210 that performs password hashing even for accounts with no usable password hash; musl's crypt() returns "*" for failed hashing including oversized passwords, causing a match against stored "*" fields.
  • Impact: Attackers can log in to accounts configured to block password authentication. On Alpine Linux official AWS and Azure cloud images, the default 'alpine' account has passwordless 'doas' privileges, potentially allowing root access.
  • Status: Fixed in OpenSSH 10.6p2; Alpine fixed packages available for releases back to 3.16. Patch available.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Systems using glibc, including Debian, Ubuntu, and Fedora, and those using PAM authentication are not vulnerable to this attack.; Accounts locked with ! in /etc/shadow are not affected either, and neither are machines where no account has a $-style password hash.; Non-Linux systems, Linux systems built on glibc, and systems that check passwords through PAM are not affected.; OpenWrt handles SSH with Dropbear by default, and Dropbear is not affected.; Containers that do not run sshd, systems with PasswordAuthentication no, and cloud images set up through cloud-init are not affected.
  • Recommended Actions: The vulnerability has been fixed in OpenSSH 10.6p2, and Alpine Linux administrators are advised to update their OpenSSH packages using apk upgrade openssh.; Admins who can't immediately install the update can mitigate the issue by turning off SSH password authentication with PasswordAuthentication no in their SSH server configuration and restarting SSH.; On Alpine, the fix is a package update followed by a restart, because upgrading the package does not restart the running sshd: Update the packages: apk upgrade -U -a Restart the server: rc-service sshd restart.; If you cannot update yet, turning off password logins also stops the attack. First make sure your SSH key login works, and keep your current session open until a new login succeeds. Then set PasswordAuthentication no, check the configuration with sshd -t, and restart sshd.

Severity unknownExploitation unknownPatchCVE-2026-109518#

Reporting
  • The Hacker News — Debian and Ubuntu APT Flaw Lets MitM Attackers Swap Verified Packages and Run Code as Root · Digest context

Affected versions unresolved. Review the linked reporting before inferring an affected version range.

Vendor guidance: lists.debian.org, ubuntu.com, security-tracker.debian.org

  • Description: A flaw in APT, the package manager for Debian and Ubuntu, allows an attacker who can modify package downloads to swap a checked package for their own; the attacker's code runs as root. The attack needs APT to retry failed downloads (default from Debian 12 and Ubuntu 22.04 onward).
  • Impact: Arbitrary code execution as root on Debian and Ubuntu systems when installing packages via compromised HTTP traffic.
  • Status: Fixed versions of APT released by Debian and Ubuntu. Patch available.
  • Affected Versions: Unresolved from supplied sources.
  • Exceptions: Older releases such as Debian 11 and Ubuntu 20.04 are not exposed by default.
  • Recommended Actions: Debian has released fixed versions of APT for CVE-2026-109518. Ubuntu published new APT builds for Ubuntu 26.10 (3.3.3ubuntu0.1), Ubuntu 26.04 LTS (3.2.1ubuntu0.1), Ubuntu 24.04 LTS (2.8.4ubuntu0.1), and Ubuntu 22.04 LTS (2.4.15ubuntu0.1). Debian 11 fixed version 2.2.5 published.

Affected Systems and Products

  • OpenSSH on musl-based Linux: Alpine Linux, OpenWrt, Buildroot, and Yocto systems running OpenSSH without PAM with password authentication enabled
  • Apple operating systems: iOS, iPadOS, macOS, tvOS, watchOS, and Safari affected by CVE-2024-27834 and CVE-2025-43529
  • Docker Sandboxes: Developer environments using Docker Sandboxes prior to version 0.51.0
  • Apache OFBiz: Servers running versions prior to 24.09.08
  • Zyxel GS1900 switches: Ten models (GS1900-8, 8HP, 10HP, 16, 24, 24E, 24EP, 24HPv2, 48, 48HPv2) running firmware prior to Patch 3
  • Debian/Ubuntu APT: Debian 12+, Ubuntu 22.04+ systems using APT with retry enabled; Debian 11 and Ubuntu 20.04 not exposed by default but may have retry enabled via user scripts

Attack Vectors and Techniques

  • Oversized password authentication bypass: Submitting passwords exceeding 256 bytes causes musl crypt() to return "*", matching the stored "*" field for password-disabled accounts and granting access
  • Pointer Authentication bypass: Exploiting improper authentication to bypass Pointer Authentication protections on Apple devices, enabling further exploit chains
  • Symbolic link sandbox escape: Using the sbx cp command with a symbolic link to trick a copy operation into accessing files outside Docker Sandbox boundaries
  • Pre-authentication remote code execution: Exploiting Apache OFBiz authentication flaws to achieve unauthenticated RCE or full admin account takeover
  • Out-of-bounds write via HTTP: Sending oversized parameters to the Zyxel GS1900 web management interface to overwrite memory and execute OS commands without authentication
  • APT package manipulation via MITM: Modifying HTTP traffic between APT and package servers using redirects and temporary errors to trigger retries and swap verified packages for malicious ones

Threat Actor Activities

  • APT29 (Cozy Bear / Midnight Blizzard): Russian state-sponsored group using compromised legitimate websites, fake sites masquerading as popular websites, and a supply chain attack via Plerdy SEO Tracker to serve malicious JavaScript and deliver information-stealing malware; linked with moderate to high confidence to exploitation of Safari and Chrome vulnerabilities
  • Kapibala / Red Heron: Chinese-speaking threat actor observed exploiting Zyxel GS1900 switches, compromising 996 devices across 48 countries; linked to the Red Heron hacking campaign, JITTERLY backdoor, and SIXZUT rootkit
  • Crafty Falcon: CERT-In tracked AI-assisted threat actor targeting Banking, Financial Services, and Insurance (BFSI) organizations in India, also targeting cryptocurrency exchanges; uses ARTEX, PentAGI, Cairn, and CyberStrikeAI tools for autonomous attack chains
  • Scattered Spider: Cybercriminal group targeting service desks via social engineering, impersonating employees to convince agents to reset passwords or register new MFA devices, bypassing knowledge-based verification
  • Kali365 / VoidProxy operators: Phishing-as-a-service platforms used in fake OpenAI, SpaceX, and Anthropic event campaigns to steal Microsoft and Google account credentials and session cookies via device code phishing and adversary-in-the-middle techniques
